## Four measurement bugs

Every one of them distorted a number I had already reported.

1. **A 6-hour segment went unenriched — 16 markets, 1 outcome captured.**
   `scripts/collector.sh` picked the session to enrich with
   `ls -t | head -1`. A directory's mtime advances when a file is created
   or removed inside it, *not* when an existing file is appended to, so a
   session that spends six hours writing into files it opened in its first
   second keeps that first second's mtime — and a 12-hour-old session
   sorted as "newest". Recovered by hand; Kalshi retention is weeks, so
   nothing was lost this time. Now enriches the last 4 sessions by
   `start_ts` from `sessions.json`, which also covers the second failure
   mode: a segment's final markets have not settled when it ends.

2. **The same bug corrupted `sweep --holdout`.** `discover_sessions()`
   sorted by mtime, so the split that is specified as chronological was
   not. It was ordering 10:12 before 04:12. Regression test added.

3. **The sweep and `score` disagreed about the same configuration** —
   +0.0075 with a CI clearing zero versus +0.0000 inconclusive. The sweep
   scored every scan; `score` has always thinned to one row per ticker per
   N seconds. Un-thinned, each market is weighted by how many times we
   happened to scan it, which is a property of when the collector started
   and stopped. The cluster bootstrap fixes the *interval* for
   within-market correlation; it cannot fix a point estimate that is
   weighting the wrong thing. The sweep now thins identically, and the two
   tools agree.

4. **The cluster bootstrap re-summed every observation on each of 2000
   iterations.** At 78 clusters over 40k observations, scoring a sweep
   cost more than the replays it was scoring — a five-config sweep ran
   15+ minutes with the worker pool long since idle. Pre-reducing each
   cluster to `(sum, count)` is the same arithmetic with the same seed and
   the same intervals, ~500× less work. Pinned against a naive reference.

## The caveat that matters most

All 71 markets come from ~20 hours of **one trending episode** — BTC ran
+5.2% (68,008 → 71,519), including +3.8% inside a single 6-hour segment.
The cluster bootstrap handles correlation within a market. It does nothing
about a regime shared across every market in the corpus.

So 71 markets is fewer effective observations than 71. Reaching 300 is not
just about the count; it is about spanning enough regimes that a single
day's direction cannot carry the result. Settled outcomes so far: 41 YES /
37 NO, comfortably inside the fair-coin band for n=78.
